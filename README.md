# ClaimFlow — ระบบจัดการเอกสารเคลมประกันดิจิทัลสำหรับโรงพยาบาล

ต้นแบบ (prototype) หน้าจอระบบจัดการเอกสารเคลมประกัน ครอบคลุมตั้งแต่แผนกต้อนรับไปจนถึงการส่งมอบเอกสารให้บริษัทประกัน ออกแบบตาม Figma: [claimflow](https://www.figma.com/design/jnmMd2Edfhi89rN3bzgxO8/claimflow) และสเปกฟีเจอร์ 5 ขั้นตอนของ HCFI

ระบบนี้เป็น **front-end prototype แบบ static** ทำงานล้วนในเบราว์เซอร์ (mock data + mock integrations) เพื่อสาธิต UX/Workflow ทั้งหมด สามารถรันบน GitHub Pages ได้โดยไม่ต้องมี backend จริง

## ฟีเจอร์หลัก

1. **แผนกต้อนรับ** — ค้นหาผู้ป่วยจากระบบ SIS ด้วยเลขบัตรประชาชน, สแกนบัตรประชาชนเข้าระบบ, เซ็นใบยินยอมผ่านหน้าจอ iPad
2. **ช่องชำระเงิน** — จับไฟล์ Invoice จาก Share Drive, จำลองการอ่านด้วย OCR เพื่อจับคู่ HN อัตโนมัติ (หรือจับคู่ด้วยตนเอง), เซ็นรับรองผ่าน iPad
3. **จัดการเอกสาร** — Dashboard ติดตามความครบถ้วนของเอกสาร ทั้งมุมมองตาราง และมุมมองกลุ่มสถานะ (Kanban) พร้อมอัปโหลดเอกสารเพิ่มเติมรายผู้ป่วย
4. **ใบสรุปจ่าย** — รวบรวมผู้ป่วยที่พร้อมเบิกเป็นชุดเอกสาร ส่งไปยัง ERP (จำลอง NetSuite) เพื่อขอเลขใบสรุปจ่าย แล้วประทับเลขกลับเข้าระบบ
5. **ส่งมอบเอกสาร** — สร้าง Token Link จำกัดอายุการใช้งาน พร้อมพอร์ทัลให้บริษัทประกัน Log-in (KYC) ก่อนดาวน์โหลดเอกสาร
6. **Audit Log** — บันทึกทุกการทำรายการ พร้อม IP, ผู้ใช้งาน และสถานะความสำเร็จ
7. **การตั้งค่า** — สถานะการเชื่อมต่อระบบ (HIS/SIS, ERP/NetSuite, Storage) และนโยบายความปลอดภัย

บัญชีทดสอบสำหรับพอร์ทัลบริษัทประกัน: `insurer_demo` / `insurer2026` (แสดงอยู่ในหน้าล็อกอินแล้ว)

## เทคโนโลยี

React + TypeScript + Vite + Tailwind CSS + React Router (HashRouter เพื่อให้ deploy บน GitHub Pages ได้โดยไม่ต้องตั้งค่า server-side routing)

## เริ่มต้นใช้งาน (Local Development)

```bash
npm install
npm run dev
```

เปิดเบราว์เซอร์ที่ `http://localhost:5173`

## Build

```bash
npm run build
npm run preview
```

## Deploy ขึ้น GitHub Pages

โปรเจกต์มี workflow `/.github/workflows/deploy.yml` ที่ build แล้ว deploy อัตโนมัติผ่าน GitHub Actions ทุกครั้งที่ push เข้า branch `main`

ก่อนใช้งานครั้งแรก ให้ตั้งค่าใน repository:

1. ไปที่ **Settings → Pages**
2. เลือก **Source: GitHub Actions**
3. Push โค้ดเข้า branch `main` (หรือกด "Run workflow" ที่แท็บ Actions)

เมื่อ deploy สำเร็จ เว็บไซต์จะพร้อมใช้งานที่ `https://<owner>.github.io/<repo>/`

## หมายเหตุสำคัญ

- ข้อมูลทั้งหมดในระบบเป็น **mock data** อยู่ใน `src/lib/mockData.ts` และเก็บอยู่ใน React state ของเบราว์เซอร์เท่านั้น (รีเฟรชหน้าจะรีเซ็ตข้อมูล) — ใช้สำหรับสาธิต UX/Workflow เท่านั้น ยังไม่เชื่อมต่อกับระบบ SIS/ERP/Storage จริง
- OCR ในหน้าช่องชำระเงินเป็นการจำลอง: หากตั้งชื่อไฟล์ให้มีเลข HN ของผู้ป่วย (เช่น `invoice_6604302.pdf`) ระบบจะจับคู่อัตโนมัติ มิฉะนั้นจะต้องเลือกจับคู่ด้วยตนเอง
- ลายเซ็นดิจิทัลใช้ HTML Canvas จำลองการเซ็นบนหน้าจอ iPad โดยตรง (ไม่ใช้ใบรับรองอิเล็กทรอนิกส์ CA) ตามที่ระบุใน พ.ร.บ. ธุรกรรมทางอิเล็กทรอนิกส์ มาตรา 9
